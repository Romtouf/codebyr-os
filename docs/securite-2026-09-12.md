# Correctifs de sécurité et chantier UID — 12 septembre 2026

État : changements locaux sur la base 1.10.1, pas une version publiée.
Les résultats ci-dessous concernent Debian 13 dans WSL et les sources du dépôt.
Ils ne constituent pas une validation du bureau GNOME, de l'installeur ou du
matériel. Aucun compte existant ni aucune donnée d'Espace n'a été migré.

## Correctifs implémentés

- **Frontières des fichiers.** `fichiers_surs.py` parcourt les répertoires par
  descripteurs avec `O_NOFOLLOW`. Les configurations sont remplacées
  atomiquement ; un lien dur ne peut plus faire tronquer un fichier de l'hôte.
  Les fichiers spéciaux sont refusés sans attendre sur un FIFO. Les transferts
  créent exclusivement leur destination et numérotent les collisions.
- **Boîtes d'envoi.** Un lien vers un dossier de l'hôte ou vers une destination
  extérieure n'est plus suivi. L'hôte copie depuis un descripteur de fichier
  ordinaire vérifié ; il ne déplace plus une cible choisie par un Espace.
  L'origine est posée sur le fichier ouvert avant sa publication. Elle reste
  un indice, pas une preuve cryptographique ni une autorisation de transfert.
- **Modèles.** Une déclaration absolue ou contenant `..` ne peut plus choisir
  un dossier hôte. Les dossiers symboliques sont refusés.
- **Restauration.** L'archive est entièrement extraite dans un dossier privé
  avant le remplacement. Les archives corrompues, traversantes, les liens et
  fichiers spéciaux sont refusés. Limites : 100 000 entrées / 20 Gio décompressés.
  L'ancien dossier est conservé sous `avant-restauration-*`. Il contient des
  données sensibles et continue d'occuper de la place jusqu'à sa suppression
  délibérée. Fermer les applications avant de restaurer reste nécessaire.
- **Échec fermé.** Sans bubblewrap, aucun Espace n'est lancé. Si le lanceur
  Jetable est indisponible, un fichier étranger n'est pas ouvert normalement.
  Les erreurs sont signalées depuis le bureau.
- **Ouverture normale.** Une visionneuse concrète remplace le retour à
  `xdg-open`, qui pouvait rappeler le gestionnaire Codebyr par défaut en boucle.
- **Réseau restreint.** Un namespace sans interface externe est imposé à tous
  les processus natifs concernés. Un socket Unix donne uniquement accès au
  proxy de cet Espace ; un relais interne fournit HTTP et SOCKS aux programmes.
  Un programme ignorant le proxy n'a pas de réseau. La liste vide bloque tout.
  Les applications sans support proxy peuvent donc perdre leurs fonctions
  réseau : pas de repli vers un accès direct.
- **Firefox.** Les préférences gérées sont remplacées par leur clé ; un ancien
  port proxy ne peut plus rester prioritaire. Le relais utilise un port stable
  dans le namespace propre à chaque lancement.
- **Blindage.** Le namespace utilisateur est obligatoire. Un filtre seccomp
  via libseccomp refuse notamment ptrace, process_vm_*, BPF, perf, userfaultfd,
  les interfaces de modules noyau et de trousseaux. C'est une liste de refus
  complémentaire, pas une garantie contre toutes les failles du noyau.
- **Flatpak.** Refus dans les Espaces blindés, jetables ou à réseau restreint /
  coupé : ses permissions ne sont pas équivalentes à celles de Codebyr.
  Une installation dédiée ne porte plus une affirmation générale d'isolation.
- **Couleurs fiables et fermeture.** La classe de fenêtre annoncée par une
  application ne lui permet plus de choisir la couleur « Banque ». La
  filiation est vérifiée avec l'heure de naissance du processus. La fermeture
  utilise un pidfd et vérifie cette même identité : un PID réutilisé ne doit
  pas faire tuer une autre application. Après mise à jour, rouvrir les Espaces
  ou se reconnecter pour recréer leurs marqueurs ; les anciens marqueurs sans
  identité ne sont plus considérés comme fiables.
- **Chaîne de livraison.** L'entrée manuelle du workflow de signature passe
  par une variable d'environnement, sans interpolation dans le code shell.
  Les tests comparent aussi les champs fonctionnels du manifeste signé.
  Les nouveaux modules sont inclus dans l'analyse statique de la CI.

## Rejouer les vérifications

Exécution locale : **254 tests réussis sous WSL Debian 13, sans test ignoré**,
dont le lancement complet de Banque et une capture Firefox ESR sans affichage
avec un utilisateur non privilégié. L'analyse Python, la syntaxe JavaScript
de l'extension, la syntaxe YAML et ShellCheck du script de paquet passent.
Les **38 fichiers** applicatifs contrôlés dans le paquet / l'arbre de l'image
correspondent aux sources, avec contrôle des permissions.

Le test Firefox en root échouait sur son propre sandbox ; il est exécuté sous
un UID non privilégié, comme sur le bureau réel. Aucun réglage de sécurité de
Firefox n'a été désactivé pour faire passer le test.

Les tests d'accès disque sécurisé nécessitent Linux. Sous Windows, utiliser WSL :

```sh
cd /mnt/c/Users/pcrom/codebyros
python3 -B -m unittest discover -s tests -v
```

Intégration sur une machine Linux **de test**, avec bubblewrap, dbus-daemon,
libseccomp2, et Firefox ESR pour le test de navigateur sans affichage :

```sh
sudo python3 -B tools/prototype_uid.py creer travail
sudo python3 -B tools/prototype_uid.py creer navigation
sudo env CODEBYR_TEST_LINUX=1 python3 -B -m unittest discover -s tests -v
```

Deux comptes système verrouillés sont créés : `cbyr-test-travail` et
`cbyr-test-navigation`, sous `/var/lib/codebyr-prototype-uid/`. Ils n'ont ni
shell de connexion ni groupe supplémentaire. Le test vérifie le refus de
lecture entre UID **sans** bubblewrap, puis teste séparément les namespaces,
le proxy et seccomp. Les comptes restent disponibles pour les prochains essais.

## UID par Espace : réalisé et restant

`tools/prototype_uid.py` est un prototype d'administration **non installé dans
le paquet**. Il crée un compte dédié, vérifie ses droits puis abandonne les
privilèges avant d'exécuter bubblewrap. Aucun service privilégié, règle sudo
ou exception polkit n'est ajouté. Aucun compte personnel n'est réutilisé.

Ce prototype prouve la séparation des fichiers entre UID ; il n'implémente
pas encore l'expérience Codebyr complète. Son lancement est sans réseau,
audio ou affichage. Il ne faut pas remplacer le lanceur du bureau par ce script.

Pour livrer cette architecture :

1. Définir un service d'administration minimal avec une identité de demandeur
   obtenue du système, jamais d'un argument UID fourni par le client. Les
   identifiants doivent être associés à leur propriétaire dans un registre
   root non modifiable par les Espaces. Aucun shell root ni chemin arbitraire.
2. Valider un canal Wayland par Espace sur GNOME, puis les permissions audio,
   les portails, les notifications et le presse-papiers. Ne jamais exposer
   le bus de session complet pour résoudre un problème de compatibilité.
3. Faire authentifier et autoriser les transferts par l'hôte ; traiter toute
   entrée venant d'un Espace comme hostile, même si son UID est connu.
4. Migrer **une copie** des données, à l'arrêt, sans suivre de liens ; conserver
   l'ancien état. Vérifier documents, profils Firefox, propriétaires, xattrs,
   sauvegardes et restauration avant de basculer le registre de lancement.
5. Tester les sessions simultanées, fermeture forcée, redémarrage, manque de
   disque et mise à jour. Garder une procédure de retour arrière testée.

Un UID distinct limite une évasion restant non privilégiée. Il ne contient
pas une compromission root/noyau. Le compte de bureau et les médiateurs
autorisés à ouvrir les Espaces restent des composants de confiance.

- Les tâches produit de `chantiers.md` (internationalisation, banques
  préremplies vérifiées, ergonomie, compatibilité matérielle, testeurs) ne
  sont pas toutes réalisées par ce lot de correctifs.

Les signatures et la publication APT/ISO n'ont pas été déclenchées. La CI
modifiée devra aussi être exécutée sur GitHub : sa présence dans le dépôt
ne prouve pas qu'un runner distant l'a déjà validée.

## Ajout du 12 septembre — io_uring

La liste de refus laissait `io_uring` ouvert. Deux conséquences, la seconde
étant la plus grave :

- c'est l'une des surfaces du noyau les plus touchées par des élévations de
  privilèges ces dernières années ;
- surtout, il **contourne seccomp** : les opérations soumises dans l'anneau
  (ouvrir, lire, écrire, se connecter) ne passent pas par les appels système
  correspondants, que le filtre ne voit donc jamais. Laisser io_uring ouvert
  offrait un second chemin vers tout ce que les autres lignes refusent.

`io_uring_setup`, `io_uring_enter` et `io_uring_register` sont refusés, avec
`pidfd_getfd` (voler un descripteur ouvert à un autre processus) et `setns`
(rejoindre l'espace de noms d'un autre processus).

`unshare` n'est **volontairement pas** refusé : Firefox construit son propre
bac à sable avec, et le bloquer désactiverait une protection du navigateur
pour en ajouter une ici.

Vérifié à l'exécution, pas seulement dans la liste : un appel mal orthographié
ne serait jamais résolu et le filtre passerait pour actif sans rien bloquer.
Les 24 noms sont résolus par libseccomp, et `io_uring_setup` renvoie EPERM
sous le filtre.

## Validation sur bureau GNOME réel — 12 septembre 2026

Machine virtuelle VMware, installation issue de l'ISO puis mise à jour par apt
en 1.11.0. Ce que l'essai a **établi**, et non déduit :

- **Le cloisonnement réseau par Espace fonctionne.** Depuis l'Espace Banque,
  une connexion TCP directe vers une adresse IP littérale échoue sur
  « le réseau n'est pas accessible » — un `ENETUNREACH`, donc aucune route du
  tout, pas un DNS qui échoue ni une connexion refusée. La même commande
  depuis le bureau aboutit. C'est le témoin qui rend le résultat concluant :
  ce n'est pas une VM sans réseau, c'est l'Espace qui n'en a pas.
  C'était le trou principal — la liste blanche ne s'appliquait qu'au
  navigateur.
- **Un Espace s'ouvre** avec son liseré coloré, malgré l'échec fermé
  nouvellement imposé en l'absence de bubblewrap.
- **`verifier-isolation` : aucune sortie de bac à sable** dans les trois
  situations — bus de session, `systemd --user`, bus système et socket X11
  tous inaccessibles ; Jetable sans réseau ni micro.
- **`verifier-poste` : six contrôles conformes**, dont le trousseau qui
  connaît la sous-clé en cours et les mises à jour réellement armées.
- **Le Blindage s'applique.** `sudo` est refusé depuis un Espace sur
  « no new privileges » : c'est la garantie attendue, observée.
- **Le presse-papiers reste cloisonné** : impossible de coller du bureau vers
  un Espace. Constaté involontairement, en essayant de le faire.
- **Le dossier Modèles est présent** dans le dossier personnel de l'Espace.

Reste à éprouver sur ce même bureau : le chargement d'un site autorisé dans le
navigateur de Banque (le chemin positif de la liste blanche), la fermeture d'un
Espace par identité de processus, un instantané suivi d'une restauration, le
refus de Flatpak dans un Espace blindé, et les deux entrées de clic droit.

`curl` n'est pas installé dans l'image : un test réseau doit utiliser `bash`
(`/dev/tcp`) ou `python3`. Un `curl` introuvable renvoie 127, ce qui ressemble
à un échec réseau sans en être un.

### Suite de la validation, même journée

- **Fermeture d'un Espace** : deux Espaces ouverts, un seul fermé depuis le
  menu du Sceau — l'autre reste ouvert. La vérification d'identité par `pidfd`
  et heure de naissance se comporte comme prévu sur un bureau réel.
- **Liste blanche, chemin positif** : le site bancaire déclaré s'affiche
  normalement dans l'Espace Banque, et un domaine non déclaré reçoit un
  « 403 Forbidden » du proxy. Le blocage ET le passage sont donc vérifiés.
- **Provenance de bout en bout** : un fichier créé dans Navigation, envoyé vers
  Travail, y apparaît avec la colonne « Espace d'origine » à « Navigation ».
  Les trois entrées de menu contextuel sont présentes.
- **Restauration** : l'observation initiale — « le fichier reste dans la
  corbeille » — n'était pas un défaut. Un fichier mis à la corbeille n'est pas
  supprimé ; l'original revient bien à sa place. En revanche, le refus de tout
  lien dans une archive était, lui, un vrai défaut, reproduit isolément et
  corrigé en 1.11.1.

Restent non éprouvés sur ce bureau : le refus de Flatpak dans un Espace
blindé, les notifications, et les sessions simultanées.
- **Refus de Flatpak, et sa contrepartie.** Dans Banque (blindé + liste
  blanche), `flatpak run` est refusé avant tout lancement, avec notification.
  Dans Personnel, il est accepté — et le système affiche que l'application
  garde son propre bac à sable Flatpak et que le liseré reste indicatif. Le
  refus distingue donc les Espaces au lieu de s'appliquer partout, ce qui
  rendrait Flatpak inutilisable sur tout le système.

## Relecture du 12 septembre — cinq écarts fermés (1.12.0)

Une relecture a comparé ce que le modèle promet à ce que le code applique.
Cinq écarts ont été corrigés le 13 septembre ; `tests/test_surface_attaque.py`
les garde fermés (21 de ses 26 tests échouaient sur le code précédent, les
autres gardent le sens inverse : ne pas bloquer un usage légitime).

1. **Navigation blindée.** Le Blindage — et avec lui le filtre seccomp —
   n'était actif que sur Banque et Jetable. Blinder Navigation imposait aussi
   de revoir les plafonds : 2 Go sans échange et 800 tâches (fils
   d'exécution) auraient tué Firefox en usage normal. Ils deviennent réglables
   par Espace (`"plafonds"`), Navigation déclarant 75 % de la mémoire et 4096
   tâches ; Banque et Jetable gardent les valeurs d'origine.
2. **Filtre réseau et réseau local.** Le proxy, qui tourne sur l'hôte,
   refuse désormais toute adresse non publique après résolution et se
   connecte à l'adresse vérifiée (pas de seconde résolution exploitable par
   un DNS changeant).
3. **Extension GNOME.** Identifiant d'Espace échappé dans les lignes de
   commande ; couleur validée à la lecture du registre et à la création.
   Précision sur la gravité : `GLib.shell_parse_argv` ne lance pas de shell,
   l'identifiant brut permettait donc d'ajouter des *arguments* à
   `codebyr-space`, pas d'exécuter une commande dans GNOME Shell.
4. **Carte graphique.** Clé `"gpu"` distincte du Blindage (comme `"audio"`),
   fausse pour Banque, Jetable et toute pièce jointe. Navigation la garde :
   la lui retirer aurait fait payer la sécurité en saccades vidéo.
5. **Noyau.** `etc/sysctl.d/91-codebyr-noyau.conf`, livré par le paquet et
   appliqué par le postinst sans attendre de redémarrage.

**Vérifié** : 297 tests ; dans WSL, avec un compte non privilégié et le code du
dépôt monté sur `/usr/share/codebyr`, Firefox ESR 140 charge
`https://example.com/` sous le Blindage complet de Navigation (seccomp compris),
capture identique à celle obtenue hors bac à sable ; `verifier-isolation`
rapporte la carte graphique absente là où elle doit l'être. WSL ne donnant
aucun DNS dans un bac à sable (`/etc/resolv.conf` y pointe vers `/mnt/wsl`), cet
essai rend `/mnt/wsl` visible ; sur Codebyr, `resolv.conf` est un fichier
ordinaire.

**Validé sur bureau GNOME réel — 13 septembre 2026** (VM VMware, 8 Go, carte
graphique virtuelle présente), paquet 1.12.0 installé par `apt install` depuis
la 1.11.1 :

3. **Navigation blindée** : 🛡 dans le menu du Sceau ; le processus principal

5. **Banque et Jetable sans carte graphique** : affichage et défilement
